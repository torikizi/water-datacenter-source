# 公開用実行成果物

このディレクトリには、決定論的な水収支、モックLLM、外部DS4を明確に分けて保存します。秘密情報、モデルファイル、DS4本体、推論キャッシュは含みません。夏季版の対象期間は2026年6月1日〜9月10日の102日間です。

## `summer_preview/`

夏季版コード変更後に生成した確認用成果物です。実DS4は呼んでいません。

### `summer_preview/inzai_comparison/`

印西・千葉ニュータウンを題材にした15比較ケースです。各ケースは102行、合計1,530日行の`water_balance.jsonl`を持ちます。比較実行は水収支だけを隔離するため、各ケースの`llm_messages.jsonl`は空です。

- 通常条件・DCなし: 住民不足0、期末地域配水バッファ27.39 ML
- 40 MW単独: 上水消費42.58 ML、住民不足0
- 3施設・合計105 MW集中: 上水消費83.26 ML、住民不足0
- 250 MW・住民優先: D39（7月9日）に配水バッファが空、上水消費132.68 ML、住民不足0
- 250 MW・比例配分: D39から住民不足、累積153.53 ML／64日、上水消費240.15 ML
- 配水池増設感度: D62（8月1日）に容量20 MLと外部初期充水10 MLを追加
- 再生水感度: 0%、2%、25%、50%。2%は国内DC実績ではなく低利用感度、25%と50%は専用供給がある反実仮想

主要ファイル:

- `comparison_summary.json`: 全比較ケースの反実仮想指標
- `scenario_comparison.csv`: ML単位へ変換した解析表
- 3つの比較SVG
- 各ケースの`water_balance.jsonl`、`summary.json`、空の`llm_messages.jsonl`

### `summer_preview/mock_agent_summer/`

固定応答の`MockProvider`を使った、再現可能な夏季エージェント因果確認です。実DS4推論ではありません。

- 102日の水収支、10会議、4役×10回＝40判断
- 40件すべて厳密JSONスキーマに合格
- 会議日: D1、D15、D29、D35、D36、D43、D57、D71、D85、D99
- D35（7月5日）に自治体が75%制限を選択し、D36からPythonが固定倍率を適用
- 制限なしの同一250 MW・住民優先ケースに対して、D36のDC取水を1.32 ML削減、最大貯水差3.96 ML
- 配水バッファが空になる日をD39からD41へ遅延
- 住民不足0、DC不足190.61 ML／67日、水収支誤差0

`summer_preview/inzai-water-game.html`は、このモック監査と決定論比較を埋め込んだ確認用HTMLです。最終提出用の実DS4ゲームではありません。

## 夏季実DS4監査

### `ds4_agent_summer_demo_v3/`

2026年8月29日に`deepseek-v4-flash`で取得した、夏季102日の実DS4監査です。

- 10会議、4役×10回＝40応答
- 40件すべて厳密JSONスキーマに合格。正規化0件、フォールバック0件
- 会議日: D1、D15、D29、D35、D36、D43、D57、D71、D85、D99
- D35に自治体が制限を選択し、D36からPythonが固定倍率75%を適用
- 制限なし反実仮想に対し、D36のDC取水を1.32 ML削減、最大貯水差3.96 ML、配水バッファ枯渇をD39からD41へ遅延
- 住民不足0、DC不足190.61 ML／67日、水収支誤差0

`llm_messages.jsonl`には全プロンプト、未加工応答、JSON解析、検証結果、プロバイダー情報を保存しています。水収支と反実仮想差は`water_balance.jsonl`と`summary.json`にあるPython計算結果です。通常の成果物生成は巨大モデルを暗黙に起動しません。

## 旧実DS4監査アーカイブ

### `ds4_agent_season_demo_v2/`

2026年8月28日にDeepSeek V4 Flashで取得した、365日・2026年8月26日開始の監査履歴です。8会議・32応答のうち29件が当時の厳密スキーマに合格し、3件は240文字超過で拒否されました。未加工応答と当時の後続判断を保持するため、現在の長文短縮境界で書き換えていません。

このv2は**夏季102日版を駆動しません**。開始日、日数、物理条件が違うため、夏季ゲームの監査入力として使用できません。D33の制限、D34の1.32 ML削減、D36からD38への遅延、365日累積値は旧実行だけの履歴です。

### `ds4_agent_season_demo/`

2026年8月27日に取得した初回の365日監査です。8会議・32応答のうち24件が厳密スキーマに合格しました。当時は発言順が住民→自治体→水道→DCで、自治体のD36制限は物理系を変えませんでした。不正形式も削除・修正せず保存し、判断が有効だったかを検証できる失敗例として残しています。このディレクトリも夏季版には使用しません。

### `ds4_agent_demo/`

外部`ds4-server`による4役×1日の疎通監査です。4件すべて短いJSONとして解析・検証に成功しています。季節比較ではなく、プロバイダー接続と監査ログ形式の確認用です。

## データ境界

夏季版の地域配水バッファは、北総浄水場配水池の公表有効容量48 MLを運用容量の代理値にし、2026年6月1日の日初を100%と置く仮定です。印西専用の観測在庫ではありません。2025年6月1日〜9月10日の我孫子アメダス降水実績と、利根川上流9ダム実績を月日対応の観測コンテキストとして表示します。降水はモデル上水供給へ変換せず、9ダム実績も地域配水計算には使いません。需要に10.5%の余裕を加えた基準供給、月別需要形状、渇水倍率、施設条件は明示したモデル仮定です。

> すべて仮説生成用です。公表情報を地域文脈として参照しつつ、水収支入力は明記した合成仮定を含みます。現実の印西市の予測ではありません。
