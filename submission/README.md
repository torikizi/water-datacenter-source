## 動作の証拠

- ルートの`./run.sh` 1コマンドで、水収支・4者判断・ゲーム画面まで生成
- `.env`にDS4接続先があれば実DS4を試し、未設定または通信失敗時は固定モックで全期間を最初から再実行
- Python 3.14.7で49件の単体テストに成功
- 夏季版は2026年6月1日〜9月10日の102日間
- 決定論的な15ケース比較を再生成し、各ケース102行、合計1,530日行の水収支を出力
- 実DS4による夏季エージェント実行は10会議・40応答で、40件すべて厳密JSON検証に成功。正規化・フォールバックは0件
- 実DS4自治体のD35（7月5日）の制限判断がD36から反映され、制限なし反実仮想に対して配水バッファ枯渇をD39からD41へ遅延。住民不足は0
- 夏季比較ではDCなしの住民不足0、250 MW比例配分感度の追加住民不足153.53 ML／64日
- 外部DS4とDeepSeek V4 Flashによる4役×1日の疎通監査も別途完了し、4件すべてJSON検証に成功
- 365日・2026年8月26日開始の実DS4季節ログは監査履歴として保存。ただし夏季102日版の物理系列やゲーム入力には使用しない

実DS4ログと決定論的`MockProvider`ログは別ディレクトリに保存し、READMEと成果物内で明示しています。DS4本体、モデル、キャッシュはリポジトリに含めません。

会議順は住民代表→水道事業者→データセンター事業者→自治体です。自治体は同一会議内の3者の発言を共有履歴として受け取ってから最終判断し、その許可済み行動だけが翌日の固定政策へ反映されます。

## 夏季版の提出状態

夏季102日の実DS4監査は`submission_artifacts/ds4_agent_summer_demo_v3/`へ生ログとして保存済みです。ルートの`submission_artifacts/inzai-water-game.html`は主画面を`DCなし`／`DCあり`の2ケースへ絞り、DCありでは40〜300 MWのPython事前計算結果を18段階から切り替えます。単一施設・D31稼働・稼働率80%・WUE 1.1・再生水0%・比例配分という固定条件では、124.6 MWまでは住民不足なし、124.7 MWから不足開始です。これは当シナリオ内の境界であり、現実の地域へそのまま適用できる安全上限ではありません。250 MWではD39から住民不足が発生し、102日累計の住民供給が153.53 ML（約7%）減ります。画面の3者／4者ボードは計算結果に応じた論点のルール表示で、LLM発言ではありません。リポジトリ外で管理する4枚PPTXは境界比較中心に更新済みです。約76秒のデモ動画は`DCなし → 124.6 → 124.7 → 250 MW`の順で住民向け上水への影響を示し、`VOICEVOX:玄野武宏(CV:ガロ)`のナレーションと動画内クレジットを収録しています。提出前に本人環境で通し再生し、YouTubeの限定公開後にも音声同期、文字の可読性、1080p画質を確認してください。

夏季版の地域配水バッファは、北総浄水場配水池の公表有効容量48 MLを運用容量の代理値にし、2026年6月1日の日初を100%と置く仮定です。印西専用の観測在庫ではありません。2025年6月1日〜9月10日の我孫子アメダス降水実績と、利根川上流9ダム実績を月日対応の観測コンテキストとして表示しますが、降水をモデル上水供給へ変換せず、9ダム実績も地域配水計算へ使用しません。基準供給、月別需要形状、渇水倍率、施設条件は引き続き明示したモデル仮定です。
